# Hello World

Practice the GitHub Flow by creating a branch, committing a change, and merging it through a pull request.

## Goals

- Create and use a repository
- Make a branch from `main`
- Edit a file and commit the change
- Open, review, and merge a pull request

## Exercise

1. Create a repository named `hello-world`, add a README, and choose whether it should be public or private.
2. From the repository's `main` branch, create a branch named `readme-edits`.
3. Edit this README on `readme-edits`. Add a short introduction or another change, then commit it with a message that explains the change.
4. Open a pull request comparing `readme-edits` with `main`. Review the diff, then create the pull request with a clear title and description.
5. Merge the pull request into `main`. Once merged, delete `readme-edits` if you no longer need it.

## How the Flow Works

Branches let you work on changes without immediately changing `main`. A commit records a change on your branch. A pull request proposes those commits for review and merging. After the merge, the changes are part of `main`.

If GitHub reports a conflict, resolve it before merging. Conflicts occur when changes on the branch overlap with changes already made to the target branch.
